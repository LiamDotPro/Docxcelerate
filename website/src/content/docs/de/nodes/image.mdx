## Jedes Feld ist ein Prop

`src`, `alt`, `width`, `height`, `align` und `href` sind einfache Props, aus dem
State berechnet, bevor das Element zurückgegeben wird. Eine Unterschrift, die je Standort
abweicht, ein Logo je Marke, ein Foto nach Aktenzeichen — all das bleibt in der
Komponente, statt zu einer Verzweigung im Template zu werden:

```tsx
export const Signature: Image = () => {
  const [state] = useState((data: MemberData) => ({
    src: data.signatureUrl,
    manager: data.managerName,
  }));

  return (
    <Image id="signature" src={state.src} alt={`Signed by ${state.manager}`} width={180} />
  );
};
```

## Aus src wird path

Das Prop heißt `src`; der aufgelöste Node nennt sie `path`. Klappen Sie *Wozu
es aufgelöst wird* bei der ersten Variante unten auf, um es zu sehen.

## Größe und Platz

Geben Sie eine Seite an, und die andere folgt den eigenen Proportionen des Bildes,
gelesen aus dem PNG, JPEG, GIF oder BMP, das es trägt (bei einem SVG aus seinem
`fallbackSrc`): `<Image src={logo} width={160} />` ist ein Logo mit 160 pt in
seiner wirklichen Form, kein Quadrat. Ohne beides ist es 120 pt breit; mit beiden
ist es die Box, die Sie angegeben haben. Ein Bild, das noch keine Bytes hat — eine
URL, ein noch nicht beantworteter Prompt —, reserviert ein Quadrat.

`align="center"` oder `"right"` verschiebt die eigene Zeile des Bildes quer über die
Spalte. Nichts schwebt, und kein Text umfließt es. In einer Zelle oder einer Form
bestimmt die Ausrichtung der Spalte beziehungsweise der Form.

## Ein Bild, das verlinkt

`href` lässt das Bild eine Adresse öffnen — einen QR-Code, einen Jetzt-bezahlen-
Button, ein Logo —, in Word mit Strg+Klick, in der Vorschau mit einem Klick. Es
gelten dieselben vier Schemata wie bei einem
[`<Text>`-Link](/de/docs/nodes/paragraph/#anders-gesetzte-wörter); alles andere
zeichnet das Bild ohne Link, weil die Adresse aus Ihren Daten stammen kann. Sein
`alt` ist das, was ein Screenreader ansagt, sagen Sie also, wohin es führt:

```tsx
<Image src={state.qr} alt="Pay invoice 1042 online" width={96} align="right" href={state.payUrl} />
```

## Dynamische Bilder

Ein dynamisches Bild wird beschrieben statt geliefert und nimmt dieselben
Prompt-Slots wie ein dynamischer Absatz.

`negativePrompt` verdient hier seinen Platz mehr als irgendwo sonst. Generierte
Bilder scheitern auf vorhersehbare Weise — eingebackener Text, erfundene Logos,
erkennbare Gesichter — und der Slot schließt das einmalig aus, im Node.

## Anmerkungen

- **Nur eine `data:`-URI reist mit.** Sie trägt die Bytes, also hat auch ein
  anderswo geschriebenes Dokument das Bild noch. Ein Pfad oder eine http-URL
  wird am Bildschirm gezeichnet, wo ein Browser sie laden kann, landet in einer
  `.docx` aber nur als Notiz: beim Packen wird nichts geladen und nichts von
  der Platte gelesen, denn die Maschine, die das Dokument schreibt, ist nicht
  die, auf der die Datei lag.
- Word bettet ein SVG nicht allein ein — gib ihm ein Raster über `fallbackSrc`.
  Der Bildschirm zeichnet das SVG, die Word-Datei bekommt das Raster.
- `alt` lohnt sich in beiden Fällen: es beschreibt das Bild in der Word-Datei,
  und ein Node, der noch kein Bild hat, druckt es an dessen Stelle.
