Docxcelerate needs **Node.js 20 or newer** and nothing else. Authoring, preview
and DOCX packing all run locally — there is no account to create and no service
to reach before you see a document.

## Install the CLI

```sh
npx docxcelerate init my-documents
cd my-documents
npm run dev
```

That is the whole first run. If you would rather have the command on your path:

```sh
npm install -g docxcelerate
dxcl init my-documents
```

Or add it to an existing repository, where `npx dxcl` then resolves locally:

```sh
npm install --save-dev docxcelerate
npx dxcl init my-documents
```

The command is `npx docxcelerate`, not `npx dxcl` — npx resolves the package
name, and the binary inside it is called `dxcl`.

## Scaffold a workspace

```sh
dxcl init my-documents
```

`dxcl init` writes a self-contained Vite workspace and runs `npm install` in it.
Called with no arguments it asks for the name, the template and the API endpoint
instead of taking them as flags:

```sh
dxcl init
```

| Flag | What it does |
| --- | --- |
| `--dir <parent-dir>` | Creates the workspace inside an existing directory |
| `--sample` | Includes a working document to read (the default) |
| `--blank` | Leaves `documents/` empty |
| `--api-endpoint <url>` | Points the workspace at a generation engine |
| `--no-api-endpoint` | Sets up without one; you can add it later |

The endpoint is only needed for documents with generated prose, and it can be
filled in at any time — see [the engine](/docs/generation/endpoint/).

## What you get

```text
my-documents/
  docxcelerate.config.json
  index.html
  package.json
  tsconfig.json
  vite.config.ts
  .gitignore
  preview/
    main.ts
    styles.css
  documents/
    welcome/
```

Everything above `documents/` is the preview app. `documents/` is your work: one
directory per document, and with `--sample` it starts with `welcome/` already in
it.

`docxcelerate.config.json` holds named presets for build and upload behaviour.
Everything else is an ordinary Vite project — open it in your editor and it will
behave like one.

## Open the preview

```sh
npm run dev
```

The preview site comes up on `127.0.0.1:4507`. Pick a document and it is
resolved against its preview data, packed into a real `.docx` in the browser,
and read back with `docx-preview` — so what you are looking at is the file
itself, not an approximation of it.

Edit any file under `documents/` and the page reloads with the change in place.

Three more scripts come with the workspace:

| Script | What it runs |
| --- | --- |
| `npm run document:new` | `dxcl document new` — a new document |
| `npm run document:node` | `dxcl document node` — a new node in one |
| `npm run documents:check` | `tsc` over every document |
