## Как его написать

Текст — это потомки элемента, подставляемые так же, как любые потомки JSX.
Языка шаблонов нет, поэтому форматирование, ветвление и множественные формы —
это обычный TypeScript, выполняемый в инициализаторе состояния, где компонент и
делает свои размышления:

```tsx
import { Paragraph, useState } from "docxcelerate/template";
import type { MemberData } from "../types.ts";

export const Greeting: Paragraph = () => {
  const [state] = useState((data: MemberData) => ({ name: data.memberName }));

  return <Paragraph id="greeting">Dear {state.name},</Paragraph>;
};
```

Компонент может быть `async` — но тот, который что-то запрашивает, может упасть
посреди сборки, поэтому лучше заранее положить значение в данные. Если вы всё же
делаете `await`, каждый хук должен быть вызван до первого из них.

## Бюджет токенов

`useAvailableTokens()` — это бюджет, выделенный данной сборкой: `2000`, если вы
не задали `availableTokens` в опциях сборки. Статические узлы могут его
игнорировать. Динамическим стоит его тратить:

```tsx
const availableTokens = useAvailableTokens();

useSetPrompts({
  generalPrompt: `Explain the change. At most ${Math.floor(availableTokens / 4)} words.`,
});
```

## Ветвление

Документ, говорящий одно из трёх, — это один компонент с тремя исходами. Дайте
каждой ветке собственный id:

```tsx
if (state.settled) {
  return <Paragraph id="balance-settled">Nothing outstanding.</Paragraph>;
}

return <Paragraph id="balance-arrears">A balance remains.</Paragraph>;
```

Разные id — это то, что позволяет разрешённому документу зафиксировать, какая
ветка досталась этому получателю, и они обязательны, как только ветвление
публикуется: движок хранит обе ветки, а id адресует ровно один узел.

Когда исходы различаются только формулировкой, вычислить строку и вернуть один
узел — значит остаться при одном id; это более старая привычка и по-прежнему
хорошая:

```tsx
const [state] = useState((data: MemberData) => ({
  line: data.settled ? "Nothing outstanding." : "A balance remains.",
}));

return <Paragraph id="balance">{state.line}</Paragraph>;
```

## Динамические абзацы

У динамического абзаца нет собственного текста; вместо него он несёт промпты и
заполнитель, заданные через `useSetPrompts` и `useSetPlaceholders` либо
переданные пропсами. Сборки предпросмотра разрешают его в заполнитель и помечают
его; сборки времени запроса отправляют промпты. Обязателен только
`generalPrompt` — четвёртый вариант ниже показывает, для чего остальные три.

## Примечания

- Оба режима разрешаются в `kind: "paragraph"`. Рендерер читает `mode`, если ему
  это вообще важно; он никогда не ветвится по тому, как узел был написан.
- Узел с собственным текстом статичен, какие бы промпты ни задал вокруг него
  общий хук. Задать и то и другое на одном элементе — ошибка.
- Пустая строка даёт пустой абзац, а не отсутствие узла. Чтобы убрать узел,
  ничего не возвращайте — `false`, `null` и `undefined` пропускаются.
- Рендереры экранируют текст. Абзац не может протащить разметку на страницу и не
  является местом для оформления.
