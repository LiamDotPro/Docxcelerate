## Как его написать

Текст — это потомки элемента, подставляемые так же, как любые потомки JSX.
Языка шаблонов нет, поэтому форматирование, ветвление и множественные формы —
это обычный TypeScript, выполняемый в инициализаторе состояния, где компонент и
делает свои размышления:

```tsx
import { Paragraph, useState } from "docxcelerate/template";
import type { MemberData } from "../types.ts";

export const Greeting: Paragraph = () => {
  const [state] = useState((data: MemberData) => ({ name: data.memberName }));

  return <Paragraph id="greeting">Dear {state.name},</Paragraph>;
};
```

Компонент может быть `async` — но тот, который что-то запрашивает, может упасть
посреди сборки, поэтому лучше заранее положить значение в данные. Если вы всё же
делаете `await`, каждый хук должен быть вызван до первого из них.

## Бюджет токенов

`useAvailableTokens()` — это бюджет, выделенный данной сборкой: `2000`, если вы
не задали `availableTokens` в опциях сборки. Статические узлы могут его
игнорировать. Динамическим стоит его тратить:

```tsx
const availableTokens = useAvailableTokens();

useSetPrompts({
  generalPrompt: `Explain the change. At most ${Math.floor(availableTokens / 4)} words.`,
});
```

## Ветвление

Документ, говорящий одно из трёх, — это один компонент с тремя исходами, а не
три компонента. Дайте каждой ветке собственный id:

```tsx
if (state.settled) {
  return <Paragraph id="balance-settled">Nothing outstanding.</Paragraph>;
}

return <Paragraph id="balance-arrears">A balance remains.</Paragraph>;
```

Разные id — это то, что позволяет разрешённому документу зафиксировать, какая
ветка досталась этому получателю, и они обязательны, как только ветвление
публикуется: движок хранит обе ветки, а id адресует ровно один узел.

Когда исходы различаются только формулировкой, вычислить строку и вернуть один
узел — значит остаться при одном id; это более старая привычка и по-прежнему
хорошая:

```tsx
const [state] = useState((data: MemberData) => ({
  line: data.settled ? "Nothing outstanding." : "A balance remains.",
}));

return <Paragraph id="balance">{state.line}</Paragraph>;
```

## Как он располагается на странице

`align` — единственное оформление, которое абзац задаёт сам, потому что
выравнивание часто и есть то, чем абзац *является*, а не то, как он выглядит:
дата прижата вправо в любой теме, как и колонка с деньгами:

```tsx
<Paragraph id="issued" align="right">{state.issuedOn}</Paragraph>
```

Всё остальное в том, как набран абзац, принадлежит теме и выбирается по имени
через `variant`. Решает блок; узел лишь говорит, какой это блок:

```ts
blocks: {
  standfirst: { align: "center", spacingBeforePt: 4, spacingAfterPt: 14 },
  quote:      { indentMm: 10, indentRightMm: 10 },
  heading:    { keepWithNext: true },
  contents:   { tabStopsMm: [{ at: 170, align: "right", leader: "dot" }] },
}
```

```tsx
<Paragraph id="lead" variant="standfirst">What this letter is about.</Paragraph>
<Paragraph id="terms" variant="contents">{"What the agreement covers\t3"}</Paragraph>
```

Собственный `align` узла побеждает `align` его блока — так же, как ячейка
побеждает свою колонку. Что блок может задавать помимо заливки, рамки и шрифта:

| | |
| --- | --- |
| `align` | как строки располагаются в колонке |
| `spacingBeforePt`, `spacingAfterPt` | интервал сверху и снизу, в пунктах |
| `indentMm`, `indentRightMm` | отступ от левого и правого полей |
| `firstLineIndentMm` | только первая строка — абзацный отступ книги |
| `hangingIndentMm` | первая строка выдвинута назад относительно остальных |
| `keepWithNext`, `keepLines` | никогда не последняя на странице; никогда не разрывается между страницами |
| `tabStopsMm` | `[{ at, align?, leader? }]` от левого поля либо от внутреннего края ячейки или фигуры. Поставьте `\t` в тексте, чтобы дойти до него |
| `lineHeight` | межстрочный интервал, кратный размеру шрифта |

Каждое из этих свойств значит на экране то же, что и в Word, и это проверяется,
а не предполагается: для каждого свойства здесь есть тест на соответствие,
который упаковывает документ, открывает его в Word и сверяет предпросмотр с тем,
что рисует Word, с точностью до миллиметра. Два ограничения следуют из
собственного формата Word, и их стоит знать: полю нужна рамка, на которой оно
держится, а левая рамка сдвигает *линию* наружу, а не текст внутрь.

Абзац внутри [`<Cell>`](/ru/docs/nodes/table/#что-содержит-ячейка) или
[`<Shape>`](/ru/docs/nodes/shape/) сохраняет всё это — свой `align` поверх
выравнивания колонки, а также отступы, позиции табуляции, рамку и заливку своего
варианта, — так что ячейка с подписью может нести пунктирный заполнитель, а
карточка — цитату с линейкой. Там позиция табуляции отмеряется от внутреннего
края контейнера, а `bleed` и `maxWidthMm`, которые являются мерами страницы, ничего
не делают.

Рамка — это одна сплошная линия, если блок не говорит иное. `borderStyle` рисует
собственную линию Word — `"double"`, `"dashed"` или `"dotted"` — на каждой
стороне, которую рисует блок: двойную линию под итоговой суммой, пунктирную
линию отрыва над квитанцией, — вместо того чтобы складывать блоки, изображая её:

```ts
grandTotal: { border: "1C2340", borderSides: ["bottom"], borderStyle: "double", weight: "bold" },
```

## Списки

Список — это абзацы, которые говорят, что они элементы. `list="bullet"` помечает
маркированный, `list="number"` нумерует:

```tsx
<Paragraph id="intro">To renew:</Paragraph>
<Paragraph id="check" list="number">Check the plan and the price.</Paragraph>
<Paragraph id="pay" list="number">Pay online, or at the desk.</Paragraph>
<Paragraph id="pay-note" list="bullet" listLevel={1}>Card and direct debit are both accepted.</Paragraph>
<Paragraph id="collect" list="number">Collect your new card.</Paragraph>
```

Элементы, написанные один за другим, — это один список, и считает рендерер, так
же как он считает страницы. В этом и вся причина не набирать номера руками:
шаг, выпавший у одного получателя, не оставляет пробела, а список, построенный из
ваших данных, — такой же `.map()`, как любой другой.

```tsx
{state.steps.map((step) => <Paragraph id="step" list="number">{step.text}</Paragraph>)}
```

Всё, что не является элементом, обрывает список, и нумерованный список после
него начинается снова с единицы. `listLevel` помещает элемент под вышестоящий:
`1` — пункт под элементом, и так до девяти уровней вглубь. Номера идут от цифр к
буквам и к римским цифрам по мере спуска, маркеры — от закрашенной точки к
пустой и к квадрату. Маркированный пункт под нумерованным шагом не мешает шагам
считаться дальше.

Нумерованный список считает цифрами, потом буквами, потом римскими цифрами,
потому что так задано по умолчанию, а не потому что иначе нельзя. `listStyle` у
первого элемента уровня выбирает нумерацию этого уровня для всего списка —
подпункты договора идут как `(a)`:

```tsx
<Paragraph list="number">The tenant agrees:</Paragraph>
<Paragraph list="number" listLevel={1} listStyle="lowerLetterParen">to pay the rent on time;</Paragraph>
<Paragraph list="number" listLevel={1}>to keep the property in good order.</Paragraph>
```

За `decimal`, `lowerLetter`, `upperLetter`, `lowerRoman` и `upperRoman` следует
точка; добавьте `Paren` для формы со скобкой. Маркеры это игнорируют.

Элемент — по-прежнему абзац. У него есть id, условие может его убрать, он
принимает `variant`, а элемент, который пишет движок, может быть элементом списка
как любой другой. Элементы стоят вместе, а интервал, который абзац оставляет под
собой, приходится после списка, а не между его элементами — если только
собственный `variant` элемента не называет интервал: он побеждает.

Два ограничения. Глиф маркера и выступ каждого элемента принадлежат рендереру, а
не теме: `listStyle` выбирает нумерацию числа и ничего больше. А элемент в
`<Shape>` рисуется как обычный абзац: рамка и так удерживает слова от своего края
тем же отступом, который нужен выступу.

## Слова, набранные иначе

`<Text>` выделяет часть слов абзаца среди остальных — термин, на котором держится
уведомление, фразу, которая куда-то ведёт:

```tsx
import { Paragraph, Text } from "docxcelerate/template";

<Paragraph id="terms">
  Payment is due within <Text bold>thirty days</Text>. You can{" "}
  <Text href="https://example.com/pay">pay online</Text>.
</Paragraph>
```

`bold`, `italic`, `underline` и `strike` говорят, как выделены слова;
`script="superscript"` или `"subscript"` поднимает или опускает их — 2 в м², 2 в
CO₂, st в 1st, — так что их набирает Word, а вы не печатаете `²`; а `href`
говорит, куда они ведут: адрес с `https:`, `http:`, `mailto:` или `tel:`.
Один `<Text>` внутри другого получает обе настройки. Он работает так же среди
слов `<Cell>` или `<Shape>`.

Это не узел. У него нет id, и ничто его не адресует. Он никогда не задаёт цвет
или размер; когда фразе нужно выделиться — сумма к оплате в предложении,
определяемый термин, — назовите блок темы, как это делает абзац:

```tsx
The amount due is <Text variant="amountDue">{state.due}</Text>.
```

До слов доходят только символьные настройки блока — `color`, `fill` как
затенение, `fontSizePt`, `weight`, `font`, `transform`, `letterSpacingEm`;
рамки, поля и интервалы принадлежат абзацу. Отметка, сказанная рядом, побеждает
блок, а ссылка сохраняет акцентный цвет темы. Адрес, не относящийся ни к одному из
четырёх видов, печатается одними своими словами, потому что адрес может прийти из
ваших данных, а предпросмотр рисует ссылку как то, на что читатель может нажать.

Конец строки в тексте — это разрыв строки, а не новый абзац, а именно это и нужно
адресу: один узел, три строки и никакого интервала, который абзац оставляет под
собой:

```tsx
<Paragraph id="address">{"Flat 2\n14 Example Road\nLeeds LS1 4AB"}</Paragraph>
```

Серии (`runs`) есть только у статического абзаца. Тот, что пишет движок, пишется
простыми словами.

### Что публикуется

Абзац хранит свой `text` целиком, так что всё, что читает слова абзаца, по-прежнему
читает одну строку. Настройки едут рядом как `runs`, каждая со своими словами:

```json
{ "kind": "paragraph", "mode": "static", "id": "terms",
  "text": "Payment is due within thirty days.",
  "runs": [
    { "text": "Payment is due within " },
    { "text": "thirty days", "bold": true },
    { "text": "." }
  ] }
```

У абзаца, в котором ничего не выделено, `runs` нет вовсе, и он публикует ровно то
же, что и раньше. Подставленные значения работают внутри `<Text>` так же, как и
везде: опубликованная серия хранит токен, и движок разрешает его на месте, так
что `<Text bold>{state.name}</Text>` выделен жирным для каждого получателя,
какой бы длины ни было его имя.

## Динамические абзацы

У динамического абзаца нет собственного текста; вместо него он несёт промпты и
заполнитель, заданные через `useSetPrompts` и `useSetPlaceholders` либо
переданные пропсами. Сборки предпросмотра разрешают его в заполнитель и помечают
его; сборки времени запроса отправляют промпты. Обязателен только
`generalPrompt` — четвёртый вариант ниже показывает, для чего остальные три.

## Примечания

- Оба режима разрешаются в `kind: "paragraph"`. Рендерер читает `mode`, если ему
  это вообще важно; он никогда не ветвится по тому, как узел был написан.
- Узел с собственным текстом статичен, какие бы промпты ни задал вокруг него
  общий хук. Задать и то и другое на одном элементе — ошибка.
- Пустая строка даёт пустой абзац, а не отсутствие узла. Чтобы убрать узел,
  ничего не возвращайте — `false`, `null` и `undefined` пропускаются.
- Рендереры экранируют текст. Абзац не может протащить разметку на страницу:
  `<Text>` — единственное оформление, и это элемент, а не строка.
