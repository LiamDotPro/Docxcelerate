## Как её написать

От вас таблице нужны две вещи: колонки и строки. Колонки вы объявляете один раз
на `<Table>`, а затем заполняете её `<Row>` из `<Cell>`.

```tsx
import { Cell, Row, Table, useFormat, useState } from "docxcelerate/template";

export const VisitLog: Table = () => {
  const { number } = useFormat("en-GB");
  const [state] = useState((data: MemberData) => ({ months: data.visitsByMonth }));

  return (
    <Table id="visit-log" columns={[{ width: "auto" }, { width: 28, align: "right" }]}>
      <Row header>
        <Cell>Month</Cell>
        <Cell>Visits</Cell>
      </Row>
      {state.months.map((entry) => (
        <Row>
          <Cell>{entry.month}</Cell>
          <Cell>{number(entry.visits)}</Cell>
        </Row>
      ))}
    </Table>
  );
};
```

Каждая колонка принимает `width` — в миллиметрах или `"auto"`, чтобы разделить
всё, что оставили фиксированные, — и необязательный `align`.

`align` у `<Table>` сдвигает всю таблицу, а не её слова: блок итогов из
фиксированных колонок с `align="right"` стоит у правого поля без колонки-
распорки, которая бы его там удерживала. Сдвинуться может только таблица уже
колонки страницы: колонка `"auto"` или `bleed` заполняют её целиком.

**Почему колонки объявляются на таблице, а не в каждой ячейке?** Потому что их
разделяют все строки, и объявление один раз — это то, что выравнивает строки.
Кроме того, ячейке остаётся сказать лишь то, что в ней лежит.

Заданная вами ширина — это ширина, которую вы получите. Таблица упаковывается с
фиксированной раскладкой, поэтому Word ставит колонки там, где вы их поместили, а
не подгоняет их под то, что окажется в ячейках, — именно это выравнивает колонку
с деньгами с итогом под ней. Это проверяется, а не предполагается: набор тестов
на соответствие упаковывает эту таблицу, открывает её в Word и сверяет каждую
границу колонки с тем, где её нарисовал предпросмотр, с точностью до
миллиметра.

## Строки — обычные узлы

Это стоит знать, потому что учить придётся меньше, чем можно ожидать.

Строки и ячейки — узлы, точно такие же, как абзац или раздел. Поэтому на них
работает всё, что вы уже знаете:

- `.map()` по вашим данным создаёт строку на каждую запись, как выше.
- Условие убирает строку так же, как любой другой узел.
- Id называют себя сами, так что придумывать их для каждой строки не нужно.

Ничто из этого не сделано для таблиц особым случаем. Именно поэтому
опубликованный счёт несёт один цикл, который проходит движок, а не таблицу,
полную исключений.

## Что содержит ячейка

Большинство ячеек содержит значение, поэтому текст идёт прямо в них:

```tsx
<Cell>{line.qty}</Cell>
```

[`<Text>`](/ru/docs/nodes/paragraph/#слова-набранные-иначе) среди слов выделяет
часть из них, а ячейка остаётся одной строкой текста:

```tsx
<Cell>Total <Text bold>due</Text></Cell>
```

Когда одной строки мало — описание с более тихой заметкой под ним, — дайте ячейке
вместо этого абзацы, и они останутся на отдельных строках:

```tsx
<Cell>
  <Paragraph>{line.desc}</Paragraph>
  <Paragraph variant="muted">{line.meta}</Paragraph>
</Cell>
```

Каждый сохраняет свои `align` и `variant` — что переносится, описано на
[странице абзаца](/ru/docs/nodes/paragraph/#как-он-располагается-на-странице).

## Строки заголовка

`header` у строки рисует её как заголовок:

```tsx
<Row header>
  <Cell>Description</Cell>
  <Cell>Amount</Cell>
</Row>
```

На каждую новую страницу повторяются только те строки, с которых таблица
**начинается**. Это важно, если вы помечаете итоговую строку как `header`, чтобы
выделить её: она всё равно рисуется как заголовок, но остаётся на месте внизу,
под цифрами, которые складывает. На вершину второй страницы её не поднимут.

Предпросмотр повторяет её тоже. Таблица длиннее страницы разрывается между двумя
своими строками — по тому же шву, по которому разрывает Word, — и заголовок
рисуется снова вверху каждого куска, так что счёт на пятьдесят строк выглядит на
экране так, как печатается.

## Строки, держащие форму

Word разрывает длинную строку между страницами там, где кончается страница, и
половина строки счёта оказывается внизу одной страницы, а половина — вверху
следующей. `keepTogether` вместо этого переносит строку целиком; поставьте его на
строку, которую создаёт `.map()`, и он достанется каждой. Строка выше страницы
всё равно разорвётся.

`height` даёт строке собственную высоту в пунктах — поле для подписи, строка
формы. Это нижняя граница, которую строка перерастает, когда ячейкам нужно
больше; `heightRule="exact"` делает её фиксированной — для листа с этикетками,
где сетка важнее слов, — и Word обрезает то, что не помещается (предпросмотр
увеличивает строку, а не прячет содержимое).

```tsx
{state.lines.map((line) => <Row keepTogether>…</Row>)}
<Row height={56}><Cell>Signed</Cell><Cell>Date</Cell></Row>
```

## Примечания

- Пустая ячейка — всё равно ячейка. Word не принимает по-настоящему пустых,
  поэтому она упаковывается как пустое поле, а не как пропавшая колонка.
- `span` растягивает ячейку на несколько колонок. `align` переопределяет
  выравнивание её колонки только для этой ячейки.
- Если задать `variant` у ячейки, он побеждает вариант строки, а тот побеждает
  вариант таблицы. Более конкретный обычно и есть тот, что вы имели в виду.
- Оба рендерера рисуют настоящую таблицу — `<table>` на экране и таблицу Word с
  объявленными вами ширинами колонок в `.docx`.
