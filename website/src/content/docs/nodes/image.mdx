## Every field is a prop

`src`, `alt`, `width`, `height`, `align` and `href` are plain props, computed from state before
the element is returned. A signature that differs per office, a logo per brand,
a photograph keyed by reference — all of it stays inside the component instead
of becoming a branch in the template:

```tsx
export const Signature: Image = () => {
  const [state] = useState((data: MemberData) => ({
    src: data.signatureUrl,
    manager: data.managerName,
  }));

  return (
    <Image id="signature" src={state.src} alt={`Signed by ${state.manager}`} width={180} />
  );
};
```

## src becomes path

The prop is `src`; the resolved node calls it `path`. Expand *What it resolves
to* on the first variant below to see it.

## Size and place

Give one side and the other follows the picture's own proportions, read from the
PNG, JPEG, GIF or BMP it carries (an SVG's from its `fallbackSrc`):
`<Image src={logo} width={160} />` is a 160pt logo at its real shape, not a
square. With neither side it is 120pt wide; with both it is the box you gave. A
picture with no bytes yet — a URL, a prompt not yet answered — reserves a square.

`align="center"` or `"right"` moves the picture's own line across the column.
Nothing floats and no text wraps around it. In a cell or a shape the column's or
the shape's alignment governs.

## A picture that links

`href` makes the picture open an address — a QR code, a Pay-now button, a logo —
Ctrl+click in Word, a click in the preview. The same four schemes as a
[`<Text>` link](/docs/nodes/paragraph/#words-set-differently); anything else
draws the picture unlinked, because the address may come out of your data. Its
`alt` is what a screen reader announces, so say where it goes:

```tsx
<Image src={state.qr} alt="Pay invoice 1042 online" width={96} align="right" href={state.payUrl} />
```

## Dynamic images

A dynamic image is described rather than supplied, taking the same prompt slots
as a dynamic paragraph.

`negativePrompt` earns its place here more than anywhere. Generated imagery
fails in predictable ways — baked-in text, invented logos, recognisable faces —
and the slot rules them out once, in the node.

## Notes

- **Only a `data:` URI travels.** It carries the bytes, so a document written
  by an engine somewhere else still has the picture. A path or an http URL draws
  on screen, where a browser can fetch it, but packs into a `.docx` as a note:
  nothing is ever fetched or read from disk while packing, because the machine
  writing the document is not the machine the file was on.
- Word will not embed an SVG on its own, so give one a `fallbackSrc` raster. The
  screen draws the SVG and the Word file gets the raster.
- `alt` is worth writing either way: it describes the picture in the Word file,
  and it is what a node with no picture yet prints in its place.
