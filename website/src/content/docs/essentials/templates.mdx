A template names a document tree so a project can point at it. Nothing in it is
rendered when it is written — evaluating the JSX only builds elements, which is
what lets a component decide what it is later, with data in hand.

## The shape

```tsx
/** @jsxImportSource docxcelerate/template */
import { Document, Section, template } from "docxcelerate/template";
import { Greeting, NextSteps } from "./nodes/index.ts";
import type { DocumentData } from "./types.ts";

export const documentTemplate = template<DocumentData>(
  <Document id="tenancy-renewal" title="Tenancy Renewal">
    <Section id="opening" title="Opening">
      <Greeting />
    </Section>
    <Section id="closing" title="Closing">
      <NextSteps />
    </Section>
  </Document>,
);
```

The pragma on line one is what wires JSX to Docxcelerate rather than to React.
Set `jsxImportSource` in `tsconfig.json` instead and you can drop it:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "docxcelerate/template"
  }
}
```

Scaffolded workspaces already have this configured.

## Computed structure

A template is written at module scope, where no data exists yet, so structure
that depends on data belongs in a component rather than in the template:

```tsx
export const Enclosures: Section = () => {
  const [state] = useState((data: DocumentData) => ({ items: data.enclosures }));

  return (
    <Section id="enclosures" title="Enclosed">
      {state.items.map((item) => <Paragraph key={item.id}>{item.label}</Paragraph>)}
    </Section>
  );
};
```

Anything falsy in the children is skipped, so `{condition && <Node />}` reads
the way it does anywhere else. Nodes without ids take one from where they sit,
which is what stops a `map` from demanding names you do not have.

This works because the list is known when the document is built. A list that is
only known per request is a different problem — see
[loops are published as loops](#loops-are-published-as-loops) below.

## Reusable pieces

A component is a plain function, so a house-style wrapper is a plain function
too. Components accept children like anything else:

```tsx
export const Letterhead: Section<{ children?: Yield }> = ({ children }) => (
  <Section id="letterhead" title="">
    <Image id="logo" src="assets/logo.png" alt="Ashcroft Housing" />
    {children}
  </Section>
);
```

A shared hook is the other half of this. Because `useSetPrompts` sets prompts on
whatever the calling component yields, house style can be applied to a node the
hook does not own:

```tsx
export function useHouseVoice() {
  useSetPrompts({
    systemPrompt: "You write for a housing association. Plain English, second person.",
  });
}
```

Any component that calls `useHouseVoice()` gets that system prompt on the node
it returns, and can still override it with a prop.

## Document projects

A document project ties a template to its style and preview data through one
entrypoint, `document.project.ts`:

```tsx
import { defineDocumentProject } from "docxcelerate/document";
import { documentTemplate } from "./document.tsx";
import { documentStyle } from "./document-style.ts";
import type { DocumentData } from "./types.ts";

export default defineDocumentProject<DocumentData>({
  id: "tenancy-renewal",
  name: "Tenancy Renewal",
  version: "1.0.0",
  template: documentTemplate,
  style: documentStyle,
  previewData: {
    residentName: "Avery Mitchell",
    propertyRef: "Flat 4, Ashcroft House",
  },
});
```

`previewData` is what the preview app resolves against. Keep it realistic —
short names and placeholder cities hide layout problems that real data exposes.

## What changes when you publish

Everything above assumes you hold the data. When you build with data in hand — a
preview, a local pack, a document written on the spot — an `if` means exactly
what it says, and a `.map()` walks the list it was given.

Publishing to [an engine](/docs/generation/endpoint/) is different. The artifact
is built **once**, against stand-in values for a request nobody has made yet,
and stored. A decision that depends on request data cannot be settled during
that build; it has to travel to the engine and be made per document.

Three rules follow, and the build enforces all three rather than letting a wrong
document reach a recipient.

### Compute per document, not per build

Interpolating a value works while publishing: it becomes the token the engine
substitutes.

```tsx
<Paragraph id="greeting">Hello {state.name},</Paragraph>
// published as: "Hello {{data.name}},"
```

Computing on one does not, because the value is not known yet. Formatting a
currency, totalling a list, comparing a date — those need a **deriver**, which
the engine runs per document:

```tsx
<Paragraph
  id="balance"
  derivers={[
    derive("currencyLabel", { output: "balanceLabel", inputs: [dataRef("balanceDue")] }),
  ]}
>
  Your balance is {"{{derived.balanceLabel}}"}.
</Paragraph>
```

`useFormat` and `useDeriver` compute during the build instead, which is right
whenever the value is already known. Reach for a deriver when it is not.

### Loops are published as loops

A branch has two arms and both can be published. A loop has as many as the
request has entries, and nobody knows that number until a document is written —
so the loop itself is what gets stored:

```tsx
<Repeat over="visits" as="visit">
  <Paragraph>Visit: {"{{ctx.visit.label}}"}</Paragraph>
</Repeat>
```

With real data this walks the collection immediately, so previews show the
repetition rather than a description of it. Published, it stays a loop and the
engine walks it, binding each entry under `as` and its position under `indexAs`,
and suffixing child ids with the index so one pass stays distinguishable from
the next.

Calling `.map()` on request data while publishing is an error that names the
`Repeat` to write instead.

### Branches multiply

Publishing a branch stores both arms, each under the condition that selects it.
Nesting branches multiplies what a document carries, so there is a limit —
`branchLimit`, 32 by default — and passing it fails the build rather than
producing a quietly enormous artifact. Lift the decision into a deriver that
yields one value, or raise the limit if the document really is that conditional.
